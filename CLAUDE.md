# CLAUDE.md — інструкції для Claude Code

Правила з `AGENTS.md` (вище) обов'язкові й мають пріоритет.

## Проєкт
Аналітична система заявок меблевої студії: три таблиці менеджерів (Олена, Ігор, Марина)
зводяться скриптом у єдину таблицю, звіт, висновки, чернетки і HTML-дашборд.
Задача й визначення — у `brief.md`. Проєкт бере освітню вправу «Збірка ШІ-агента за 90 хвилин»
за навчальну основу; реалізація й розширення описані у `README.md`. Файли вебінару до репозиторію
не додаються і не є власністю проєкту.

## Робоча директорія
Корінь поточного репозиторію є робочою директорією. Запускай команди з нього та працюй лише
з файлами репозиторію.

## Мова
- Спілкування з користувачем — російською.
- Усе, що є частиною проєкту (звіти, дашборд, підписи, висновки, чернетки, коментарі в коді) — українською.
- Імена файлів, змінних і функцій — латиницею.

## Структура
| Шлях | Призначення |
|---|---|
| `webinar/` | матеріали вебінару (тільки читати) |
| `data/` | вхідні таблиці `zayavky_*.csv` (зараз — штучні демо-дані) |
| `tools/` | Python-скрипти: генерація демо-даних, звіт, дашборд |
| `reports/` | актуальні результати (перезаписуються при кожному запуску): `zvedena.csv`, `zvit.md`, `managers.md`, `chernetky.md` |
| `history/` | незмінний архів звітів `zvit-<дата>.md`, `zvit-<дата>-2.md`, … |
| `dashboard/` | `dashboard.html` |
| `agents/` | описи ролей агентів |

## Як працювати
- Цифри у звітах і висновках — тільки з виводу скриптів у `tools/`. Перед записом висновку звір кожну цифру з виводом.
- Таблиці в `data/` не переписувати вручну і не читати повністю: рахує скрипт.
- Тільки стандартна бібліотека Python 3 (`python3`). **Не встановлювати додаткових пакетів**; якщо без пакета не обійтися — спершу запитати користувача.
- Жодних зовнішніх сервісів (Google Drive, Gemini, Antigravity тощо) без окремого дозволу.
- Не видаляти й не перезаписувати вихідні файли; генератор демо-даних перезаписує CSV лише з прапорцем `--force`.
- **Під час роботи над звітами не змінювати вихідні CSV у `data/` і генератор `tools/generate_demo_data.py`** без окремого дозволу користувача.
- **Архів `history/` не перезаписувати і не видаляти**: кожна версія звіту зберігається; новий зміст — нова версія з суфіксом -2, -3…
- Файли в `reports/` можна перегенеровувати: це актуальні результати.
- **Git-коміти не створювати без дозволу користувача**; налаштування Git не змінювати.

## Команди
```bash
python3 tools/generate_demo_data.py            # створити демо-CSV у data/ (seed 20261102)
python3 tools/generate_demo_data.py --dry-run  # лише перевірити специфікацію, нічого не записувати
python3 tools/zvit.py                         # звіт: reports/ (перезапис) + history/ (нова версія лише при зміні)
python3 tools/build_dashboard.py               # автономний dashboard у dashboard/dashboard.html
python3 -B -m unittest discover -s tools -p "test_*.py" -v   # автоматизований набір тестів
```
